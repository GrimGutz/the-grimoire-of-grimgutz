# Автоматизация 0.15.1

Исправлены контексты ходов в боях без привязки к сцене, очистка Region/MeasuredTemplate, отмены и параллельные повторные запросы GM. Параметры хода фиксируются до асинхронных действий, включая сроки эффектов и состояние Лидера. Присутствия Лидера по-прежнему не проверяют зрение, слух, стены и невидимость.

## Новые механики

- Кристаллизация: выбранное оружие и доступная обычная/договорная ячейка; штатный расход после выбора. Эфирная буря: выбранная пара оружий и нативная досягаемость 30 футов. Минута для обеих способностей — согласованное домашнее правило, не срок из PDF.
- Ритуал защиты: неподвижный круг 30 футов в пределах 60 футов, 10 минут. Иммунитеты союзников и половинная скорость врагов действуют внутри; пересечения не уменьшают скорость повторно. Чужие эффекты не удаляются. Разум, тело и душа усиливает только концентрацию; восстановление контроля со второго уровня расходует бонусное действие.
- Регенерирующая душа: перед первым применением выберите недостаток кнопкой его карточки. Условия окружения подтверждает GM. Без решения неизвестные условия не считаются разрешёнными. Проверяются пороги по уровням, иммунитеты, 0 хитов и отключение до конца следующего хода. Пустые эффекты не создаются; временные хиты хранят происхождение в служебном флаге.
- Духи Ритуалиста: параметры уровня/СЛ/модификаторов сохраняются при призыве. Агония срабатывает на подходящие попадания/урон враждебным существам, Кровавая песня лечит на половину подтверждённого окончательного урона, Великие возможности выдают временные хиты выбранным получателям, Скорбная песня предлагает слепоту/глухоту и повторные спасброски без повторного урона. При смене контроля используется текущая принадлежность токенов.

## Совместимость и границы

Публичные методы и automation config версии 1 сохранены. Старые карточки, ручные правки и старые духи без снимка не заменяются молча. Для новых кнопок и вариантов духов нужен обновлённый экземпляр карточки/новый призыв; конфликты смотрите через `inspectAutomation`. Запас ресурсов и выборы не сбрасываются при обычном обновлении.

Старые эффекты Кристаллизации/Эфирной бури без выбранного оружия сохраняются, но не усиливают все оружия по догадке: диагностика отмечает `legacy-weapon-scope-missing`; примените способность заново с выбором оружия. Неопределённые применения новых баффов и Ритуала защиты сохраняются в `nativeApplications` и показываются в панели. Подтверждённый расход не возвращается и не повторяется автоматически после сбоя записи или перезагрузки.

Полный консервативный [реестр покрытия](AUTOMATION_COVERAGE.md) содержит и оставшиеся частичные/ручные механики. Наличие обработчика не означает полного покрытия правила. Сюжетные условия, ручное перемещение, решения участников и неоднозначные старые документы не автоматизируются по догадке.

## Проверки

Локально проходят 225 сценариев, включая исходные 188. Реестр проверяет полноту списка, реальные вложенные документы NPC и регистрации действий. Пустой шаблон пассивного эффекта оставлен только для служебной Укреплённой души — сопротивление включается по источнику заклинания, без постоянного сопротивления любому урону. Пересборка допускается после закрытия мира и `node tools/check-local-packs.mjs`; затем `npm run check`. LOG/LOG.old не коммитятся. Push выполняется отдельным запросом.

## Оставшаяся проверка

Реестр содержит 939 записей: 258 с нативными данными/известными обработчиками, 249 частичных, 79 явно ручных и 353 без подтверждённой связи. Последняя группа — очередь точечной сверки, **не 353 доказанные поломки**. В частности, описание дополнительной атаки, владения или сюжетного бонуса не является основанием создавать постоянный эффект. Следующая работа: установить обработчики для таких записей, сверить исходное правило и сценарий, затем исправлять только воспроизведённые дефекты.

Без Midi-QOL/его подтверждённого потока событийные части духов и подавление регенерации по типу полученного урона требуют ручного контроля. Смена контроля учитывается по текущему disposition токенов; нейтральные посторонние существа не считаются союзниками защитного круга. Решение GM об окружении недостатка регенерации нужно обновлять при изменении этих условий.

Живые сценарии **ещё не подтверждены**: игрок без прав изменения чужих актёров, два GM, разные сцены, несвязанные токены, перезагрузка с ожидающим событием, круг на разных сетках и повторные применения в реальном Midi-потоке. Перед игрой требуется эта приёмочная проверка; локальные тесты её не заменяют.
