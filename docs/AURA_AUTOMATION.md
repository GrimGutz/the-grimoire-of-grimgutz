# Ауры с привязкой к токену

Версия 0.14.26. Локальные проверки выполнены; игровая проверка в Foundry требуется отдельно.

## Поведение

Для постоянной ауры достаточно соответствующей особенности на актёре. Для временной — примените её активность. GM автоматически создаёт один круг с радиусом из карточки, центрированный на токене. Он реализован как Region с нативной `attachment.token`: Foundry перемещает круг вместе с токеном на каждом кадре анимации, без отдельного сетевого перемещения трафарета. Вручную размещать его не нужно. На любой сетке круг остаётся круглым (`gridBased: false`, `highlightMode: shapes`); единицы сцены и высота учитываются. Скрытый источник не показывает область игрокам, но механика продолжает действовать.

Цели определяются по самому кругу через Midi-QOL, без противоречащей ему второй проверки диагонального расстояния. Постоянные эффекты дополнительно пересчитываются после завершения анимации. Синхронизация использует сохранённую конечную позицию токена, не промежуточный визуальный центр, и не переписывает неизменённую привязку.

Баффы и уязвимости существуют только внутри области. При выходе или выключении источника удаляются только эффекты этой ауры; собственные свойства персонажа сохраняются. Одинаковые числовые бонусы не складываются. Перемещение и обновление документов не вызывают дополнительный урон.

Союзники и враги определяются отношением токенов (`disposition`). Для нескольких фракций или нестандартных отношений выбор подтверждает GM.

Если старую вручную изменённую карточку нельзя автоматически обновить, выбор доступен через `module.api.chooseCarnageAuraType(actor)`.

## Midi-QOL и события

Броски выполняются нативными активностями Midi-QOL с UUID существующей области и конкретными целями. Новые шаблоны, действия, ячейки, ресурсы и концентрация не расходуются. Макрос активации не вызывается повторно; эффекты «до следующего действия/попадания» владельца не истекают от автоматического срабатывания ауры. Настройки Midi определяют автоматическое изменение хитов или создание карточки применения урона.

Обслуживает один активный GM. Повторные события одного хода/атаки не дают второй бросок; отметки сохраняются на токене для смены GM и перезагрузки. Рукопашные события игроков передаются этому GM через проверяемый запрос. Отмена броска атаки не считается подтверждённой атакой. Тайм-аут/ошибка Midi — результат для проверки GM, не повод автоматически бросать второй раз.

Для спасбросков и урона активный GM должен открыть соответствующую сцену: Midi использует canvas. При другой сцене показывается предупреждение, прямое небезопасное изменение хитов не подменяет Midi. Постоянные эффекты, привязка и получение временных хитов работают и на других сценах.

Обычный NPC при переходе от положительных хитов к 0 считается умершим. Персонаж при 0 хитов — не умерший: нужно явное состояние «Мёртв». Для NPC со спасбросками от смерти GM может установить `actor.setFlag("the-grimoire-of-grimgutz", "auraDeathRequiresStatus", true)`. Для явного иммунитета к болезни доступен `auraDiseaseImmune`. Размер и место смерти фиксируются до очистки призванного существа. Ручное изменение временных хитов прекращает однозначный учёт их источника; неоднозначный запас при отдыхе не удаляется молча.

Остаются подтверждаемыми: магическое обнаружение, специальное назначение спасброска против нежити, необычные препятствия видимости/слышимости, дополнительный урон Ауры командования, симптомы и лечение скрытой болезни. Мини-мифаль не привязывается к токену: по его описанию он неподвижен.

Присутствия Лидера с выбором получателей и требованием одновременно видеть и слышать источник не заменяются безусловной аурой для всех союзников. Их дополнительные реактивные бонусы остаются по карточке; универсальный радиус для всех вариантов не назначается без правила из источника.

## Разработка

- `shared/aura-definitions.mjs`: источник, радиус, отношения целей, условие работы, постоянный эффект или событие.
- `shared/aura-templates.mjs`: нативные привязанные Region и выбор целей через их UUID.
- `shared/auras.mjs`: синхронизация принадлежности области и постоянных эффектов.
- `shared/aura-events.mjs`: очередь, события ходов/смертей/атак, защита от повторов, выбор типа и учёт временных хитов.
- `midi/aura-workflow.mjs`: временная копия активности без повторной активации; `midi/area-workflow.mjs` сохраняет нативные стадии бросков.
- События: `sourceStart`, `sourceEnd`, `targetStart`, `targetEnd`, `meleeAttempt`, `death`. Для ответной атаки, ограниченной радиусом, задаётся `requiresInside`; `ignoreTraits` передаётся нативной активности Midi. Не добавлять урон в обработчик движения.
- После изменения карточек закрыть мир и выполнить `npm run check`. При изменении только runtime — `npm run verify`.

## Игровая проверка

Переместить источник и цель через границу; выключить и повторно включить ауру; проверить крупный и скрытый токены, две одинаковые ауры и два GM. Для Пламени провести нужный ход и рукопашную атаку с промахом/отменой; убедиться, что ресурс не расходуется повторно. Для болезни проверить успех/провал и сохранение после выхода. Для душ — NPC/PC при 0 хитов, удаление призыва и отдых с более высокими временными хитами другого источника.

Для Живучести: атаковать из круга и длинной досягаемостью снаружи; проверить промах, отмену, сопротивление огню и иммунитет, обновление временных хитов и истечение минуты. При плавном движении круг должен оставаться на токене, в том числе при изменении высоты и цвета области.

Для Преданности: проверить спасбросок от смерти бессознательного союзника внутри/снаружи круга, отмену преимущества помехой и отсутствие преимущества на обычных спасбросках.
