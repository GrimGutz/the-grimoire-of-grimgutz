# План проверки автоматизации

Порядок: сначала поломки, затем ошибки правил, затем улучшения. Каждый законченный и проверенный блок — отдельный коммит. Push выполняется отдельным запросом.

## 1. Не работает — критический приоритет

- [ ] Жизненный цикл временных эффектов Foundry 14 / DAE: создание, истечение, удаление, повторное включение. Проверять `duration.value/units` и `start`, а не только устаревшие поля.
- [ ] Таймер не должен начинаться заново при изменении имени, иконки или флага эффекта. Проверить обновления с вложенными и плоскими ключами.
- [ ] Очистка эффектов на обычных и несвязанных токенах; запуск после загрузки мира и изменения игрового времени.
- [ ] Ауры: исчезновение источника/цели, выключение автоматизации, повторное включение, удаление зоны, отсутствие дубликатов при одновременных событиях.
- [ ] Призывы: валидные формулы и документы, создание токена, отсутствие второго призыва при двух клиентах, понятная обработка ошибки.
- [ ] Проверить импорт runtime, регистрации hooks и обработчиков действий, наличие реальных автоматизаций за описаниями карточек.

## 2. Работает неправильно — правила и взаимодействия

- [ ] Пассивы: отсутствие двойного бонуса, удаление после удаления особенности, восстановление после импорта, только подходящие условия.
- [ ] Ауры/зоны: союзники и враги, скрытые токены, единицы расстояния, ход получения урона, отсутствие двойного урона.
- [ ] Баффы оружия и состояния целей: подходящее оружие/цель, длительность, повторное применение, сопротивления и спасброски.
- [ ] Ресурсы, отдых, уровни классов и трансформаций; отмена диалога не должна тратить ресурс.
- [ ] Проверить Midi-QOL hooks по установленной версии системы и модуля, а не по одному наличию названия hook в исходниках.

## 3. Улучшения

- [ ] Общий небольшой модуль длительности вместо дублирования в классах и большом runtime.
- [ ] Поведенческие проверки для найденных ошибок; включить их в стандартную команду проверки.
- [ ] Удобная диагностика эффектов и причин недоступности без засорения обычного чата.
- [ ] Расширять автоматизацию только после подтверждения правильности основного пути; явно отмечать случаи с решением Мастера.

## Проверки и границы

- Исходная проверка `npm run validate`: успешно (29 классов, 421 особенность).
- Локальные проверки не заменяют проверку в работающем Foundry. Сценарии, которые требуют игровой сессии, отмечаются отдельно.
- Не затрагивать несвязанные пользовательские изменения и не коммитить служебные LOG-файлы LevelDB ради самого аудита.
- План обновляется фактами и результатами вместе с каждым исправлением; невыполненное не отмечается выполненным.
