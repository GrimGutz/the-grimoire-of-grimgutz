# План проверки автоматизации

## Повторная реализация по утверждённому плану

- [x] Диалоги Сосуда духа, критический порог D&D5e, сохранение длительности без перезапуска (поведенческие регрессии).
- [x] Общая последовательная синхронизация, несвязанные токены при загрузке/создании, изоляция ошибок отдельных обработчиков.
- [x] Подтверждаемые запросы игрок → активный GM на выбранной сцене; проверяется серверный senderId. Группы и расход выполняются последовательно по владельцу и откатываются при подтверждённом провале. Поздний ответ после тайм-аута сохраняется.
- [x] Длительность и нулевые хиты призывов; потеря концентрации делает духов Ритуалиста враждебными, есть изгнание и восстановление контроля. Нативная концентрация создаётся на копии активности без изменения карточки.
- [x] Уникальность по семейству способности; обновление управляемых значений сохраняет полученный урон, 0 хитов и ручные изменения. Старые актёры без снимка не перезаписываются.
- [x] Геометрия измеряется сеткой сцены и ближайшими занятыми клетками; футы переводятся в единицы сцены. Скрытые токены учитываются, граница скрытого источника скрыта. Очистка ограничена сценой; движение не обходит всех актёров. Аура маскировки Полого добавляет сильнейший бонус союзникам.
- [x] Сопротивление заклинаниям, нативные активности призывов, защита после подтверждения damage-card, повторные спасброски Ужасающей старости. Иммунитет состоянию предотвращает наложение; перевод хода назад не запускает turn-end повторно. Взаимодействие с живым Midi-QOL проверять отдельно.
- [ ] Диагностика, реальные регистрации обработчиков, проверка оставшихся классов и прогрессии.
- [ ] Финальная сборка; игровые сценарии проверять отдельно от Node-тестов.

Групповой призыв: при частичном провале отменяется вся группа. Тайм-аут означает неизвестный результат, а не основание автоматически возвращать ресурс.

Порядок: сначала поломки, затем ошибки правил, затем улучшения. Каждый законченный и проверенный блок — отдельный коммит. Push выполняется отдельным запросом.

- [x] Очистка включает синтетических актёров всех сцен, загрузку мира и игровое время; запись выполняет только активный GM.

- [x] Призывы: проверены нормализация формулы HP и ошибка создания актёра; параллельный уникальный призыв создаёт один документ и токен, socket обслуживает активный GM, повторный requestId не обрабатывается.

## Проверки и границы

- Исходная проверка `npm run validate`: успешно (29 классов, 421 особенность).
- Локальные проверки не заменяют проверку в работающем Foundry. Сценарии, которые требуют игровой сессии, отмечаются отдельно.
- Не затрагивать несвязанные пользовательские изменения и не коммитить служебные LOG-файлы LevelDB ради самого аудита.
- План обновляется фактами и результатами вместе с каждым исправлением; невыполненное не отмечается выполненным.
- Полная сборка и валидация `npm run check` пройдены после основных исправлений. `npm run verify` проверяет правки скриптов без повторной пересборки packs; поведенческие проверки — 20 сценариев.

## Подтверждённые находки и проверка в игре

- Убраны невалидные единицы `minute/hour/day` из временных эффектов (Foundry 14 принимает множественные формы).
- Старый preUpdate перезапускал таймер на любом обновлении и мог отменять истечение эффекта; старый сборщик не учитывал синтетических актёров.
- Исправлено: ауры оставляли эффекты при выключении автоматизации и теряли дубликаты в Map. Четыре поведенческие проверки покрывают выключение, уход цели, параллельные вызовы и повторное включение.
- Исправлено: истёкшее Масло чёрной магии продолжало добавлять урон, оружейные баффы учитывали подавленные эффекты, Демоническая живучесть продолжала выдавать временные хиты. Обновление временных хитов Демонолога и Сосуда духа теперь выполняет один клиент.
- Исправлено: Сдвиг в сторону Мерцающего имел длительность «раунд + ход», хотя описание требует конец текущего хода. Теперь это отдельное событие `turnEnd`; до события бонус остаётся доступным.
- Общий helper длительности используется для оружейных баффов, состояний целей, Потока и Пламени исчадия. Наличие старого эффекта больше не означает наличие действующего бонуса.
- Исправлено: socket призывов слушали все GM-клиенты; параллельные уникальные призывы могли одновременно не найти существующего актёра. Теперь есть выбор активного GM, проверка владельца запроса и блокировка на время создания уникального существа.
- Исправлено в общих синхронизаторах пассивов: одинаковые эффекты терялись при группировке и могли складывать бонус несколько раз. Удаляются дубликаты, обновляются источник, состояния и длительность. Удаление особенности убирает её эффект (поведенческая проверка).
- Проверены сигнатуры основных Midi-QOL hooks по установленному исходнику: `preAttackRollConfig` получает workflow, `preTargetDamageApplication` — token и context. Перенос на другие hooks ради переноса не требуется.

## Следующая очередь

1. Игровая проверка истечения и повторного включения источников аур, включая старые сохранённые эффекты. Не считать весь аудит завершённым по одним локальным проверкам.
2. Пройти классы группами: описание → условие → hook/эффект → расход → отдых. Начать с Лидера, Сосуда духа и Мерцающего, затем остальные классы и трансформации.
3. Проверить скрытые токены и расстояния на разных сетках. Сейчас ауры и зоны используют расстояние между центрами и исключают скрытые токены; это может отличаться от правил стола. Ауры обслуживают сцену активного GM.
4. Проверить состояния, где спасбросок/согласие Мастера выполняется вручную, и отмену диалогов после системного расхода ресурса. Не заявлять такие пути как полностью автоматические.
5. Проверить обновление характеристик уже существующих уникальных призывов при росте уровня, окончание длительности призывов и очистку временных шаблонов зон.
6. Добавить диагностический отчёт по выбранному актёру и сократить обходы всех актёров при частых движениях токенов после проверки корректности.
- В Foundry после перезагрузки проверить: включить Пламя исчадия → продвинуть игровое время на 60 секунд → источник и граница исчезают; восстановить ресурс и включить снова. Повторить с несвязанным токеном. Изменение имени эффекта в середине минуты не продлевает длительность.
- Отдельно проверить эффекты до конца хода: удаление на нужном событии, без преждевременной очистки на чужом ходу.
